# LiteCP audit — 27 October 2026

This review covers the Go backend, browser workflows, installation scripts, backup/restore and migration handling, PHP extension management, optional application hosting, FTP account state, and mail provisioning. It fixes confirmed defects; it is not a guarantee that every possible bug or vulnerability has been found.

## Repairs

| Area | Defect and resulting behavior |
| --- | --- |
| File editor | An editor opened for one website could save using a newly selected website. The editor now retains its website identity, ignores obsolete open requests, and prevents concurrent saves. |
| Page navigation | Recent Activities and Application Hosting did not always load when navigation changed browser history without a hash-change event. Both load through the navigation hook. Activity responses cannot overwrite newer results; application configuration preserves an intentionally empty setup command. |
| Application source privacy | Configured or disabled Python/Ruby/Node applications could fall back to static/PHP routing and expose source files. Configuration now immediately installs maintenance routing. Disabling keeps maintenance routing, including state-save failures. Upload application source only after saving its configuration. |
| Application TLS and recovery | Routing changes now use current certificate directives and recover the exact prior configuration after failed validation/reload. An unsuccessful application start keeps source protected. |
| Application lifecycle | Newly created and explicitly stopped containers use `restart=no`; boot restart is enabled after a successful start. Missing command-output logs produce an error instead of false success. Demo website removal does not invoke host container commands. |
| FTP | Unreadable account recovery metadata is rejected before credential changes, avoiding rollback with an empty snapshot. |
| Mailbox creation | The browser previously enabled mail-domain routing before validating the mailbox. A website's first mail domain and mailbox are now validated and committed together, with configuration rollback on persistence failure. Email-only domains still require explicit creation. |
| SSL and cron | Failed certificate attempts preserve the website's previous SSL status. Failed cron persistence restores the actual previous cron setting. |
| PHP extensions | Failed PHP restart after a package change attempts restoration of the previous requested package state and service. The legacy endpoint cannot remove protected baseline modules. No unrelated packages are removed. |
| Backup downloads | Only completed archives whose manifest, website identity, backup ID and size match can be listed, downloaded, or staged. Symlink backup directories/files are refused. |
| Restore database selection | SQL files inside website content are no longer offered as database dumps; only SQL members from `databases.zip` are eligible. |
| Migration stages | Retained failed/partial stages no longer consume all three usable stage slots. Symlink stage directories are rejected. Partial data is retained for review. |
| File compression | Final archive publication refuses an existing destination, including a file uploaded while compression was running. |
| Installation | Shared proxy normalization no longer resets unlimited File Manager uploads to approximately 2 GiB. Standard older configurations receive the dedicated upload route. Certificates and custom route headers are preserved. |
| MySQL reporting | Documentation distinguishes AlmaLinux's Oracle 8.4 repository from Ubuntu's distribution package. Installation reports the actual running MySQL version when available. No database upgrade is performed by this audit. |
| Ubuntu DNS verification | Verification reads live resolver routes instead of counting every known DHCP upstream. A global default route no longer falsely appears changed because another link has DNS servers. Conflicting link default routes are rejected before configuration/restart; existing split-domain routes remain unchanged. |

## Verification

Regression coverage includes Go fixtures for state rollback, source privacy, actual Nginx configuration parsing, extension recovery, FTP recovery metadata, backup completeness, database dump selection, failed migration stages, concurrent archive destinations, and fresh/legacy installer upload configuration. Browser logic has automated Node tests for navigation and editor races. Tests use temporary fixtures rather than production websites/databases.

Final results:

- Full Linux Go suite with race detector: passed (`GOMAXPROCS=1 go test -race -p=1 -count=1 -timeout 8m .`, 32.564 seconds).
- Go static checks: passed (`go vet -p=1 .`).
- Node workflow/File Manager tests: 12 passed; all browser JavaScript syntax checks passed.
- Documentation navigation check: all 17 manual sections loaded.
- Live-source Python helper tests: 6 passed.
- All installer shell syntax checks passed. Fresh/legacy upload normalization fixtures passed twice for idempotence.
- Generated enabled/disabled application configurations passed real `nginx -t` checks using isolated temporary configuration prefixes; the server was not launched by those fixtures.
- phpMyAdmin sign-on PHP syntax passed with the installed PHP 8.3 runtime (`-n -l`).
- Deployed administrator API checks passed: state, 1,324 PHP catalogue entries, activities, retention policy, optional hosting, migration jobs, website backups and FTP listing. File Manager listed all 20 root entries under the running service restrictions.
- Protected GET endpoints returned HTTP 401 without authentication. New browser asset markers and the 17-section manual were verified from the running panel. Current resolvers remained `8.8.8.8` and `8.8.4.4`.

The previous panel binary is retained on the server for recovery. No database schema upgrade or production data deletion was performed.

## Limits

- Fresh Ubuntu/AlmaLinux installation, real server reboot, and a complete migration from an external cPanel/Plesk server require separate test hosts/source credentials. Installer configuration fixtures do not prove a clean operating-system installation.
- Production checks are read-only apart from authentication and the panel binary update. They do not create/delete real websites, databases, mailboxes or FTP accounts, restore over live content, or execute untrusted application commands.
- Browser workflow tests are automated logic tests; a complete visual/browser acceptance pass remains separate.
- External email delivery, webmail DNS/TLS setup, and remote FTP client connectivity require their respective external configuration and end-to-end checks. Existing mail/webmail deployment limitations are not represented as resolved by this audit.
- Unrelated pre-existing working-copy changes are preserved outside this audit commit. No distributable ZIP is created.
